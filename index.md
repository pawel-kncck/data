# Data Learning Program
{: .no_toc }

A personal, self-paced program to learn **databases**, **data engineering** and **data analytics**,
from SQL basics to an end-to-end data platform and an analysis I can defend.
{: .fs-6 .fw-300 }

## What this is

This site is a curriculum I designed for myself. It is organised as **five phases** that build on
each other, and each phase is split into **modules** of one to two weeks. A module is not a
reading list. Every module has:

- **Why this matters** and concrete **learning outcomes**;
- **Study**: a small, opinionated set of resources (mostly free);
- **Practice**: exercises that force retrieval of what I studied;
- **Build**: a mini-project that leaves an artefact behind;
- **Check yourself**: questions I should be able to answer without looking;
- **Done when**: the checklist that decides when I move on.

## The phases

| Phase | Theme | Modules | Weeks |
| --- | --- | --- | --- |
| [0 · Setup](tracks/00-setup.md) | Tooling, environment, habits | 1 | 1 |
| [1 · Databases](tracks/databases/index.md) | SQL, modeling, internals, transactions | M1–M4 | 7 |
| [2 · Data engineering](tracks/data-engineering/index.md) | Files, pipelines, orchestration, warehousing, distributed data, streaming, quality | M5–M11 | 9 |
| [3 · Data analytics](tracks/analytics/index.md) | Metrics, statistics, EDA, visualization, communication | M12–M16 | 6 |
| [4 · Capstone](capstone/index.md) | One end-to-end project | — | 4 |

At **8 hours a week** that is about **27 weeks**, roughly six months. The plan is a default, not a
contract: the [roadmap](program/roadmap.md) explains how to speed up, slow down or reorder.

## How to use it

1. Do [Phase 0](tracks/00-setup.md) first. Everything else assumes a working local setup.
2. Work modules in order inside a phase. Phases 2 and 3 can be interleaved after Phase 1.
3. Every week, write a short entry in the [learning log](log/index.md).
4. Tick boxes in the [progress tracker](program/progress.md) only when the module's *Done when* list is complete.
5. When something in the program is wrong or boring, change the program. It lives in a git repo for a reason.

## Principles in one line each

Projects over tutorials · Retrieval over rereading · Ship something every module · Write to think ·
Depth in one stack, breadth by reading. More in [Principles](program/principles.md).
